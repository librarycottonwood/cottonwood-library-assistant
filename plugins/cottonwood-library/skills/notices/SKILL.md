# Notice banner

Follow library-assistant for conversation and the current CMS publishing route. Technical steps (banner fields, dates): repository `assistant/content/notices.md`. Read it before editing.

The banner shows across the top of every page between a start and end date, then disappears by itself.

## Banner wizard

Ask one at a time; skip what they already said.

1. "What should it say?" — then tighten it to one short sentence ("Closed Thursday, Nov 26 for Thanksgiving. Happy holidays!").
2. "Which days is the library closed?" — the exact days, even for a holiday ("Just Thursday the 26th, or Friday too?"). Never assume. If the library stays open (shorter hours, closing early, a reminder), note that instead. Repeat the days back with weekdays.
3. "When should it start showing?" — default: now.
4. "When should it come down?" — default: the end of the last closed day. Repeat dates back with the weekday.
5. "Should it link anywhere?" — optional, e.g. a news post.
6. "Want to post it on Facebook too?" — after saving, use the social skill.

The closed days and the banner's dates are separate. The website leaves Story Time and other regular programs off its calendar only on the closed days (fields: `assistant/content/notices.md`, "Banner days vs closed days"). If you can't tell whether the library closes, ask; don't guess.

Preview and ask to save.

## Change or remove

Find the banner, confirm it, edit or take it down, preview, save. If the closed days change, update them too. Expired banners can be cleaned up anytime; they're already hidden.

Regular hours changing for good isn't a banner — that's an hours update, handled by library-assistant.
